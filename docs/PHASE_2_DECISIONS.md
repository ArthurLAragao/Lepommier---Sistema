# Phase 2 implementation decisions

Inspected the actual clean `ce9724c` repository, required documents, existing code, migrations, shared contracts, native dialog, tests, lockfile, runtime and portable PostgreSQL harness. Foundation patterns and stack are retained. Docker remains absent on PATH. Verification uses bundled Node 24.19.0 through its explicit executable and the npm CLI, not host Node 25.3.0. The old readiness probe verifies connection only; authenticated installation state additionally requires migrated identity tables. Documentation's production-DB network description was aspirational: only development Compose currently exists.

Only User, Session, AuditEvent, InstallationState and bounded LoginThrottle tables are added. No future operational tables. Preserve StoreSettings and its original migration. A singleton InstallationState row is locked in every security-sensitive transaction, serializing setup, account changes and session issuance. Its closure cannot be reversed by update/delete triggers. Account writes recheck the actor/session under this lock, enforce optimistic versions, a five-active-account limit and at least one active owner. Audit actor FKs restrict deletion; audit events are append-only.

Login identifiers are trimmed/lowercased ASCII, 3–32 characters, immutable after creation, with a database normalization check and uniqueness. Display names are separate. Argon2id uses 19 MiB, two iterations and one lane, with library-generated salts; 12–128-character passwords are not trimmed/truncated. Two concurrent password jobs maximum; extra work is rejected temporarily.

Opaque 256-bit session cookies contain no account data. Only SHA-256 token digests are stored. One active session per account; login also invalidates the cookie being replaced. Absolute 12-hour lifetime, no sliding/inactivity extension. Password changes, resets, role changes and account disabling revoke sessions. Browser auth credentials remain in HttpOnly, SameSite=Strict, Path=/ cookies. Secure follows configured HTTPS origin, with an explicit local HTTP exception independent of NODE_ENV. No cookie Domain. Cookie-authenticated reads recheck DB state. Expired/revoked session cleanup is bounded and keeps seven days of diagnostic history.

Mutations require an exact configured Origin, JSON and the non-simple `X-Pommier-CSRF: 1` header, with cross-site Fetch Metadata rejected. Missing/null Origin is rejected; no credentialed CORS is enabled. This is the established custom-header/preflight approach plus strict origin validation, not a secret synchronizer token. Host validation protects against accidental DNS rebinding. Setup additionally checks the actual direct peer IP (127.0.0.1, ::1, or IPv4-mapped loopback) with trustProxy=false; forwarded headers cannot authorize it.

The installer generates a 256-bit secret in a gitignored, non-public local file with an exclusive-create command. It is read locally by the authorized installer and entered into a masked setup field; it is never fetched from metadata, put in a URL/storage, or printed by the generator. Setup closure and owner creation commit together. Login throttles persist across restart: 60/source and 8/normalized identifier per fixed 10-minute window; rejected attempts do not prolong a lock. At most 2,048 keys; expired keys pruned in bounded batches. Failed login audit is recorded only for admitted attempts. Authorization denial audit is coalesced per user/window. These local-host defaults may need tuning after a real shift.

Diagnostic logs contain event/error type and correlation IDs, never bodies, credentials or cookie values. Audit metadata has an explicit whitelist. No production seed; optional development fixture command must be opted into against a distinct local `_dev` DB, with installer-chosen credentials. Test fixtures use fresh disposable databases; no existing database is reset.

Sources: [OWASP password storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html), [OWASP CSRF custom headers/origin validation](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html), [node-rs Argon2](https://github.com/napi-rs/node-rs/tree/main/packages/argon2). A working security foundation is not a complete operational store release.
