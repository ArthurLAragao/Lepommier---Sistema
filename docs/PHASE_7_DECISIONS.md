# Phase 7 decisions

Baseline inspected: clean `main` at `02e68aeb368092bec07d319c14ae193ea104a700`, seven migrations, Phase 0–6 implementation and existing security/privacy/inventory/order/cash protections. Current executed evidence is in PROGRESS.md; definitions are in REPORT_METRICS.md.

- Reporting is an operational read model over existing source records, not accounting, bank settlement, fiscal issuance or reliable profit. Thirteen bounded tabular views cover daily summary, fulfilled sales, product sales, method summaries, timestamped payments/refunds, order intake/current state, completed production, purchased receipts, waste, inventory, cash sessions, one customer's history and current alert sources. No speculative report warehouse or chart dependency.
- OWNER receives the real dashboard and authorized exports. MANAGER explicitly receives financial, stock, cash, single-customer and recorded-cost reporting without exports or customer private fields. PRODUCTION receives only permitted stock/production/waste views. CASHIER retains existing operational/current-session access, without financial reports or owner dashboard. Named permissions and server-selected columns apply to every route, lookup, source link and export.
- Each read validates the actor/session in one short PostgreSQL REPEATABLE READ, READ ONLY snapshot. It does not acquire the global security write lock. Statement timeout is 1.5 seconds, transaction timeout seven seconds and acquisition wait two seconds. The bounded export finishes its read before taking the existing short authorization/audit lock; revoked authority discards the export. Concurrent commits after a read snapshot appear on refresh. No data inconsistency is replaced by invented zeroes.
- Business periods are inclusive Fortaleza dates represented by half-open instant ranges, at most 366 days, no future day. Browser timezone is not authoritative. Presets refresh server date. `generatedAt` and business date identify freshness; no automatic live subscription or comparison percentages.
- Fulfillment, order creation/confirmation, payment and refund use their own timestamps. Net fulfilled value is snapshot gross minus allocated discounts, before refunds. Net receipts subtract recorded refunds once. Later refunds leave earlier fulfillment intact. A zero-total draft counts as intake; existing zero-total confirmation/completion remains rejected. Customer history retains the existing profile service and adds a period-filtered single-customer view without PII.
- Product grouping uses immutable IDs. Catalog name/code/category are explicitly current; historical prices/item discounts come from snapshots, including inactive products. Full-order refunds are not invented as per-product refunds. Physical period opening/closing derives from the append-only inventory ledger; reservations/availability are explicitly current. Drift makes available stock unavailable, never silently repaired.
- Cash uses Phase 6 source totals and immutable closing snapshots, selected by opening date. Cash tender/change, Pix and cards do not inflate physical drawer cash. Operational counted difference and integrity failure are separate. Current/latest cash source integrity is checked without changing original figures.
- Current alerts are separate from historical periods. Expired stock requires physical units and an entered date before today. Near-expiry requires the operator's explicit 0–30-day horizon. No guessed low-stock threshold, shelf life or food-safety guarantee. Ready/overdue/upcoming-unpaid/paid-invalid-reservation orders and cash review/integrity link to their exact filtered source reports.
- Pages have 20 rows; totals cover the full filter. Server-only allowlisted sorts/filters and bound SQL parameters prevent query interpolation. Export uses a new explicit consistent snapshot of the same filters, rejects more than 1,000 rows without truncation, uses UTF-8 BOM/semicolon/formula-safe escaping and server filenames. Monetary CSV headers explicitly say centavos; instants are ISO with timezone. No customer directory/contact/CPF/notes, public download URL or retained export dataset. Safe audit stores scope/filter summary/count, not exported rows.
- Additive `202610170008_reporting_indexes` supplies nine date-plus-ID indexes for genuine global range queries. No table/history rewrite; all seven previous migrations and lockfile are preserved. A populated seven-migration upgrade compares source rows before/after.
- No synthetic records enter manual databases. The previously empty disposable port-3336 preview may be reused only after a fresh emptiness/installation check and isolated upgrade verification. Physical legacy folder/database names remain documented. Preserved populated Phase 4/5 runtimes/databases and their shared PostgreSQL cluster are not upgraded or stopped for tests. Fingerprints are not a backup.

No new dependencies, cloud service, external resource, public interface, Docker/TLS/LAN verification, restore guarantee, operational release or Phase 8 work is implied. High-volume acceptance and a human operator/assistive-technology pilot remain pending.

## Verification-discovered driver deadline correction

A retained owner-concurrency regression exposed `Query read timeout` during transaction control. The existing two-second pg client query timer also covered COMMIT, shorter than the existing 20-second transaction budget. A real deferred audit trigger delaying only COMMIT by 2.2 seconds reproduced a premature HTTP 500 before the fix. The bounded client deadline is now 25 seconds, allowing the original transaction budget plus protocol completion; connection timeout remains two seconds and pool size five. Reporting's server statement/transaction/acquisition limits remain 1.5/7/2 seconds, and authentication/test budgets are unchanged. No transaction, constraint or audit guard is bypassed. The delayed-commit regression requires a successful response and exactly one export audit event; its temporary function/trigger exist only in an isolated test DB and are removed. Earlier uninstrumented errors cannot all be retrospectively attributed to this defect, but the deadline defect itself is reproduced and fixed. Frozen Phase 4/5 runtimes remain historical, not silently patched.
